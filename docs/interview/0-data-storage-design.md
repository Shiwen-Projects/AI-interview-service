# 🗄️ Data Storage Design

This document describes the storage model currently implemented in the backend.
PostgreSQL is accessed through TypeORM, while uploaded CV files are stored in
Supabase Storage.

## 📋 Sessions table

TypeORM entity: `InterviewSession`  
Database table: `sessions`

| Property | Database type | Constraint/default | Description |
| --- | --- | --- | --- |
| `id` | UUID | Primary key | Generated by the service before the session is inserted |
| `post` | varchar | Required | Target role or position |
| `jobDescription` | text | Required | Full job description |
| `cv` | jsonb | Required | CV metadata in the shape `{ id: string, name: string }` |
| `cvContent` | text | Required | Text extracted from the uploaded PDF during session creation |
| `status` | varchar | Default: `generating` | Session lifecycle status |
| `createdAt` | timestamp | Generated by TypeORM | Creation time |
| `updatedAt` | timestamp | Generated by TypeORM | Last update time |

### 🔄 Session status

The application defines four status values:

- `created` — the session and CV are ready, but question generation has not started.
- `generating` — the SSE endpoint is generating questions through DeepSeek.
- `ready` — generation finished and the generated questions were saved.
- `error` — question generation failed.

Although the entity column defaults to `generating`, the create-session flow
explicitly saves new sessions with `created`.

## ❓ Questions table

TypeORM entity: `InterviewQuestion`  
Database table: `questions`

| Property | Database type | Constraint/default | Description |
| --- | --- | --- | --- |
| `id` | UUID | Primary key | Generated before each question is inserted |
| `sessionId` | varchar | Required | ID of the owning session |
| `question` | text | Required | Generated interview question |
| `createdAt` | timestamp | Generated by TypeORM | Creation time; also determines display order |
| `updatedAt` | timestamp | Generated by TypeORM | Last update time |

The intended cardinality is `session 1 → N questions`. At present, `sessionId`
is stored as a regular column: the entity does not define a TypeORM relation or
database foreign-key constraint.

`category`, parent-question relationships, and answers are not implemented yet.

## 📄 CV storage

1. The backend accepts PDF files up to **5 MB**.
2. `SupabaseStorageService` generates a separate UUID for the CV.
3. The original file name does not change and be uploaded as `${name}` to the bucket configured by
   `SUPABASE_STORAGE_CV_BUCKET`.
4. The session stores `{ id: cvId, name: originalFileName }` in its `cv` column.
5. PDF text is extracted during session creation and persisted in `cvContent`,
   so question generation does not need to download or parse the file again.

The CV ID and session ID are different UUIDs. The storage service can download a
CV by ID, but its controller is not currently registered in a NestJS module, so
there is no active public CV download or signed-URL endpoint.

## ⚙️ Database configuration

- Database engine: PostgreSQL
- Connection: `DATABASE_URL`
- Entity registration: `autoLoadEntities: true`
- SSL: enabled with `rejectUnauthorized: false`
- No migrations are currently included in the repository
